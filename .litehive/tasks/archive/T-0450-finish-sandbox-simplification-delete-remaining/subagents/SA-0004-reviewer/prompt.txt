Goal:
Bubblewrap backend was deleted in commit 14d340e7, leaving ~819 LOC of sandbox scaffolding (litehive/agents/sandbox.py, litehive/agents/_sandbox.py, litehive/sandbox/git_wrapper.py, SandboxLauncher, SandboxedAdapter wired into manager.py) with no working backend. Instead of deleting, add a Docker backend so sandboxed execution actually works. Keep the SandboxLauncher/SandboxedAdapter abstractions, replace the bwrap-specific launch path with docker run. Image should contain the engine binaries and git; mount the task worktree; mount engine auth (~/.codex, ~/.config/gh, etc.) read-only; pass through LITEHIVE_* env; enforce the same git-wrapper merge protection that bwrap used to enforce.

Acceptance criteria:
- Docker backend exists and SandboxLauncher can launch an engine process inside a container
- external_engine_sandbox config key supports docker as a backend value; default is still host (docker opt-in)
- Worktree directory is bind-mounted into the container and the engine writes to it the same way as host mode
- Engine auth directories (codex, claude, gh, etc.) are mounted read-only so sandboxed engines authenticate without copying credentials into the image
- litehive/sandbox/git_wrapper.py protection (blocking destructive git ops outside merge_resolving) still applies inside the container
- A task can be run end-to-end with sandbox=docker; an integration test exercises the path
- SandboxedAdapter, policy_summary, and related abstractions survive; only dead bwrap-specific code is removed
