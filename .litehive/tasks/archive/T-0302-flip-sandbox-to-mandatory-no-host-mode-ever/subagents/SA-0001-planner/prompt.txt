Goal:
Complete the work started in T-0286. Remove the SandboxLauncher.wrap_invocation code path that returns the raw invocation unchanged when external_engine_sandbox.enabled is false. If a sandbox profile cannot be resolved or the runtime is unavailable, raise SandboxError. Remove the 'host' string from SandboxPolicySummary.summary. Make external_engine_sandbox.enabled either hardcoded true or delete the flag entirely. When the daemon starts, verify that the chosen sandbox backend is actually usable (bwrap can create a namespace, or docker is reachable) and refuse to start the pool otherwise. Set backend to bubblewrap by default because it is already available and faster than docker on this host.

Acceptance criteria:
- SandboxLauncher.wrap_invocation raises SandboxError when the resolved profile is not enabled; there is no code path that returns the unwrapped invocation
- SandboxPolicySummary.summary never returns the literal string 'host'; if somehow called in an invalid state it raises
- external_engine_sandbox.enabled is either removed from config schema or hardcoded to always-true — no user-toggleable way to disable sandboxing
- Daemon startup runs a probe that verifies the configured backend (bubblewrap or docker) can actually create a sandbox; if it cannot, the pool refuses to start with a clear actionable error
- .litehive/config.yaml default backend is bubblewrap with runtime_binary bwrap; existing docker config is still supported for hosts where bwrap is unavailable
- Tests verify that spawning any subagent role through the pipeline with sandbox disabled raises (no escape)
