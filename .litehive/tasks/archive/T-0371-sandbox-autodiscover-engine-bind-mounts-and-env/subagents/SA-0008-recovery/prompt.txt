Goal:
Current sandbox per-engine policies in .litehive/config.yaml are hardcoded with absolute paths like /home/alexey/.codex and /home/alexey/.nvm/versions/node/v24.13.1. This is brittle: (1) breaks across operators/hosts, (2) breaks when the operator upgrades node (nvm version changes), (3) leaves stale entries when an engine is uninstalled, (4) silently misses engines that are installed later. Replace the hardcoded policy with runtime autodiscovery that probes shutil.which('<engine>') for each known engine, walks up to the node-cli root or binary dir, checks for the expected session state dir (~/.codex, ~/.claude, ~/.copilot, ~/.gemini, ~/.config/opencode, ~/bin + ~/.goz), and builds a fresh ExternalEngineSandboxPolicy for only the engines that are actually installed. Wire it into SandboxLauncher so the config can carry just 'enabled: true' without the hardcoded bind lists. Add a CLI command 'litehive sandbox refresh' (or similar) that prints the discovered policies so the operator can audit or persist them.
